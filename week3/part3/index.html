Part 1

The transformation matrices used in part 1 are:

  • The translation and scaling matrix, $M_{st}$, that maps the projected Z-coordinate from $[-1,1]$ to $[0,1]$, so OpenGL-style projection matrices can be used.
  • An orthographic projection matrix, $P$.
  • As the cube already has the right coordinates (in the range $[0,1]$), there was no need for a model matrix, as no transformation was necessary. You could say there's an implicit model matrix $M$, which is just the identity matrix.
  • A view matrix, $V$, to put the cube into an isometric view.

The model-view-projection matrix is then simply $M_{st}PV$. If you want to write the implicit model matrix as well, the full expression would be $M_{st}PV\!M$.

Part 2

For part 2, the same $M_{st}$ matrix was used along with:

  • A perspective projection matrix, $P$.
  • A view matrix, $V$, to make the camera look up the Z-axis, with some distance from the origin.
  • A translation matrix, $T$, to put the cube's centre at the origin for easier rotation.
  • A matrix for rotation around the vertical axis, $R_y$.
  • A matrix for rotation around the X-axis, $R_x$.
  • The code does a shorthand, but each cube has another translation matrix along the X-axis, $T_i$ to separate them from each other.

The three cubes then have the following model matrices:

  • $M_1 = T_1T$
  • $M_2 = T_2R_yT$
  • $M_3 = T_3R_xR_yT$

Each model matrix is then transformed by the view-projection matrix to get a model-view-projection matrix for each cube, so everything combined would be:

  • $M_{MVP,1} = M_{st}PVT_1T$
  • $M_{MVP,2} = M_{st}PVT_2R_yT$
  • $M_{MVP,3} = M_{st}PVT_3R_xR_yT$
